# 2D Part Animator — 正式設計方針 D1

決定日：2026-09-30。現行実装：添付 `2D_Part_Animator_v6_Supreme(1).html`。
状態：設計審査完了／実装未開始。今回はアプリケーションコードを変更しない。

## 結論と対象

採用：**v6の一部を流用して中核エンジンを作り直す**。
最終構成は **TypeScriptの共通編集エンジン＋PixiJS/WebGL2描画＋三角形メッシュと描画レイヤーのハイブリッド＋骨格/IK/局所変形/軽量spring＋ローカル推論＋Tauriデスクトップ配布**。

対象はまず成人キャラクター1人のイラスト、全身または上半身、元の視点を保った小～中程度の動き。独立レイヤーのない画像にも対応する。複数人物は対象人物を選択し、初版では複数人物の同時リグを行わない。
人体推定と部位境界は候補生成であり、アニメ絵を含む全画像で自動成功するとは約束しない。欠落部位・大きな遮蔽・画面外の体は明示する。大きな視点変更、真の3D回転、見えない構造の忠実な復元は対象外。
自動処理が失敗しても、ポイント配置・クリック選択・ブラシ補正で同じ編集エンジンに到達できることを製品要件とする。

## 現行v6のコードから確認した制約

- `initRigPoints` は画像寸法に固定比率を掛けるだけで、画像解析をしていない。
- 腕脚候補は肩→手首／股関節→足首の直線カプセル。肘・膝を通る抽出ではない。
- 描画は部位全体のaffine変形。骨の長さ、関節中心、接地を制約しない。
- `computePose` の親子同期は移動・角度等の数値加算。親の変換行列で子の支点を運ぶ方式ではない。
- 胸・腰・胴体の重複マスクが元画像の同じ画素を何度も描き得る。
- 背景補完はキャラクターを含む元画像のぼかし。隠れた背景を推定していない。
- 暗い線のリングは既に膨張したマスクへ加算されるため、暗さ判定が実効的な除去範囲の選別になっていない。
- 再生中も各部位の全画像マスク読取、ぼかし、部位キャンバス生成を繰り返す。
- 再生停止で姿勢が変わる。保存は設定の一部が対象外で、マスク読込完了順にレイヤーが追加される。復元順序・デコード失敗時の扱いを改める必要がある。

## 1. 推奨する最終アーキテクチャ

責務を「文書モデル」「解析」「素材生成」「リグ/モーション」「描画」「編集UI」「保存/出力」「プラットフォーム接続」に分割する。UIやDOMをエンジンの正本にしない。

文書モデルは原画像、座標系、対象人物、骨格、部位所有マスク、合成アルファ、背景修復マスク、背景プレート、部位の隠れた領域の補完素材、メッシュ、ウェイト、局所変形、重なり、モーションクリップ、ユーザー補正を保持する。原画像は不変。
解析結果は信頼度・可視性・モデルID付きの提案として返す。ユーザー補正を正本とし、再解析で勝手に消さない。重い解析/素材生成はキャンセル可能なジョブ、結果には世代IDを付け、古い結果を新しい画像に適用しない。
素材を変更した時だけ再計算し、再生時は骨格・少量の頂点データ・GPU描画のみ更新する。

## 2. Canvas 2D / WebGL / WebGPU

| 対象 | 採用 | 理由 |
|---|---|---|
| 主描画 | PixiJSのWebGL2 | 動的メッシュ、テクスチャ、合成を既存GPU基盤に任せる。最初からGPU APIを二重実装しない |
| マスク/ブラシ/画像入出力 | Canvas 2D、可能ならOffscreenCanvas | 画素編集や既存入力処理に適する。毎フレームの変形描画には使わない |
| ONNX推論 | ONNX Runtime WebのWebGPU、WASMへフォールバック | 描画と推論のバックエンド選択は別。WebGPUを動作必須条件にしない |
| WebGPU描画 | 将来の差替え点のみ確保 | 初版の必須機能にしない。WebGL2が扱える規模を先に測定 |

WebGL2が使えない端末には静止画編集と分かる診断を提供する。旧affineアニメを自然な全身変形の代替として扱わない。GPUコンテキスト喪失時はCPU側の文書モデルから再構築する。
PixiJSのMeshは頂点、UV、index、shaderを扱える。ONNX Runtime WebのWebGL推論はmaintenance modeであり、描画WebGLとは分けて考える。[S1][S2]

## 3. レイヤー / メッシュ / ハイブリッド

**描画順と遮蔽にはレイヤー、変形には三角形メッシュを使うハイブリッド**。
胴体は連続メッシュ、腕脚は関節をまたぐメッシュ。髪・服・装飾は前後関係や異なる揺れが必要な箇所だけ独立させる。頭・硬い小物では剛体変形も許可する。
輪郭・穴・関節位置を制約した三角形分割を既存ライブラリで生成し、関節/輪郭/柔らかい部位を細密化する。細長い三角形と反転を検出する。ソースUVは固定し、変形は頂点を動かす。単なる矩形グリッドを最終品質の基盤にしない。

## 4. bone / IK / skinning / spring

骨格の基準はroot→骨盤→背骨→胸郭→首→頭。左右の腕は胸郭から鎖骨/肩→上腕→前腕→手、脚は骨盤から大腿→下腿→足。
通常再生はFKとIKの混合。手足をドラッグした時は2-bone IKと曲げ方向ヒント、角度制限、到達距離制限を使用する。足固定/手固定を設定できる。
GPUの2D linear blend skinningを基礎にし、頂点ごと最大4ボーン、ウェイト和1、解剖上隣接する骨だけへ接続する。遮蔽物をまたいで近い骨へ割り当てない。
LBSだけで潰れる関節は角度依存の補正変形と局所の長さ/面積制約で補う。胸などは骨と独立した局所変形フィールド。springは物理的な副次運動に使い、リグ全体を大型物理エンジンで解かない。

## 5. 身体構造自動推定方式

処理は対象人物の領域抽出→姿勢候補→可視性/左右/骨長チェック→骨格付き部位候補→ユーザー確認。
姿勢候補の初期バックエンドはMediaPipe Pose LandmarkerのIMAGEモード。33点を製品の簡潔な骨格へ変換し、不要な細点はUIに出さない。人物全体のsegmentationだけで腕・髪等の意味付き分割が得られると解釈しない。[S3]
部位抽出の初期評価候補はMobileSAMのONNX版。画像embeddingをキャッシュし、骨格から生成した正/負の点と領域でマスク候補を絞る。単なるSAMの出力を人体パーツラベルとみなさない。[S4]
推論が失敗した場合だけ、全身/上半身テンプレートと少数点の手動配置へ移る。固定比率テンプレートは「自動認識した骨格」と表示しない。

## 6. アニメ絵対応方式

写真向け推定器の結果をそのまま採用しない。切抜き・複数解像度等の候補生成、人体の接続関係、可視性、元画像の輪郭、ユーザー点を合わせる。特徴的な頭身を一般人体比率へ無理に直さない。
低信頼点だけを強調し、3～5点程度の重要点修正から残りを補助する操作を目指す。ただし修正点数は保証しない。左右はキャラクター本人基準を内部の正本とし、UIには画面側も示す。
頭身・姿勢・遮蔽・線画・衣装の異なる少なくとも30枚の権利確認済み評価画像で、関節誤差、修正点数、部位修正量、失敗率を測る。
MediaPipe/MobileSAMのアニメ絵適合性は本審査では未検証。品質ゲート未達なら、同じ解析インターフェース内でアニメ領域向け学習済みモデル/追加学習へ差し替える。学習データと配布重みが揃っていると仮定しない。自動化達成前に「アニメ絵をほぼ無修正で解析できる」と宣言しない。

## 7. 部位分割方式

| v6の区分 | 新しい扱い |
|---|---|
| karada | 胸郭～腹部の連続メッシュ。首/頭は必要に応じ独立 |
| mune | 左右の局所変形領域。原則、胴体から切り離さず同じ画素を再描画しない |
| koshi | 骨盤ボーンと骨盤周囲の変形領域。背骨との連続性を保つ |
| arm_L / arm_R | 肩から手までの各連続メッシュ。上腕/前腕は骨で制御 |
| leg_L / leg_R | 股関節から足までの各連続メッシュ。大腿/下腿は骨で制御 |
| 追加 | 髪の前/後/束、服の裾/袖、装飾。必要箇所だけ分ける |

視覚的な前後分離が必要なところだけテクスチャを切る。接触している別部位は負の点/ブラシで分離する。分割境界はユーザーが固定できる。
画素の所有マスクと柔らかい表示アルファを分離し、重複描画を管理する。胴体内の胸/腰はウェイト領域であり、部位レイヤーではない。

## 8. 腕脚・関節

肩/股関節は実際の接続点を支点にし、肘/膝には曲げ用の複数頂点列を配置する。関節付近のウェイトを滑らかに接続し、必要なら曲げ補助ボーンを使う。
肩の付け根は鎖骨と胸郭へ分配し、肘/膝の内側の潰れ・外側の伸びを補正する。手首/足首では手/足の形をなるべく保つ。
接合部は共有の接続拘束＋小さな隠し重なり領域で裂けを抑える。別メッシュであっても同じ接続点の変換を使用する。
初期姿勢での骨長と曲げ方向を基準とし、誇張した絵も保持する。指一本ずつの自動リグは初版の必須要件にしない。

## 9. secondary motion

髪は根元を固定した短いspringチェーン。服は身体ボーンで基本追従した後、裾/袖等の局所領域にspringを適用する。
胸など柔らかい部位はアンカー＋左右の制御点＋滑らかな影響範囲。移動・回転・加速度を励振に使い、変位/伸縮/面積変化を制限してメッシュへ伝える。全物体の流体的soft-bodyは採用しない。
プリセットは呼吸、柔らかい揺れ、腰の左右/円/8の字、上下リズム、前後感、微振動、余韻。前後感は小さな拡縮/局所圧縮/前後重なりで作る2.5D表現。実際の奥行き回転とは区別する。
成人向けを含め、すべて同一の一般的な局所変形/副次運動基盤を使う。

## 10. 親子同期・遅延・spring

評価順は **共通のクリップ時刻→主動作/FK→IK/接地→ボーンのワールド行列→副次運動→関節補正/局所変形→skinning→描画**。
親子同期はrest/bind行列とローカル行列の合成。親の回転・拡縮で子の支点も正しく移る。attachされた関節そのものを遅延させない。
遅延は部位の追加角度/局所制御点の応答にのみ入れ、付け根は同期させる。springの操作は柔らかさ、減衰、最大揺れの3つを基本とする。
内部は固定1/120秒刻み、描画は補間。長い中断では積分を無制限に追い付かせず、表示再開時に定義済み状態へ復帰する。低性能環境では副次運動の点数と描画品質を下げる。
停止は現在時刻/姿勢を保持し、原姿勢復帰は別操作。シーク/動画出力は同じ固定刻みで再計算し、状態checkpointをキャッシュする。ループは周期入力＋事前安定化で継ぎ目のspring差を減らす。
sin波は周期入力の一手段として残す。部位が互いに独立したsin波で揺れる構成は廃止する。

## 11. 背景補完

背景補完と、腕の下の胴体等の「隠れていた部位の補完」を別ジョブとする。
静止する背景プレートは再生前に一度生成する。透明画像は透明な背景を維持する。単色/単純背景は周辺色、局所補間、既存画像修復処理で高速に補う。
複雑な背景はローカルinpaintingモデルを使う。第一評価候補はLaMa系。[S5] ただし元のLaMaのONNX変換とWebGPU/WASM実行がそのまま成立するとは仮定しない。演算互換性、解像度、VRAM、タイル境界、アニメ背景品質を検証し、適合する配布モデルを確定する。重い処理はTauri側のローカル推論経路も使用できる。
除去対象は背景から切り出すキャラクター領域。再生範囲で露出する背景と部位接合部を優先し、必要以上に大面積を再生成しない。描かれていなかった領域は推定であり、正解は一意でない。
修復プレビュー、再生成、クローンブラシ、外部背景読込を用意する。別モデルの検証が難航しても単純背景/手動補正で編集を止めない。ただし複雑背景の自動補完品質未達を完成扱いしない。

## 12. 残像・主線除去

マスクを「切出し用の所有マスク」「合成用アルファ」「元位置の修復用マスク」に分離する。人物を切り出す際にその輪郭もテクスチャへ含める。
修復マスクは人物の実際の輪郭と局所線幅から必要な分だけ外へ広げる。暗さだけで背景の黒線を吸い込まない。線の連結性、人物境界への接続、ユーザーの保護ブラシを使って範囲を絞る。
人物を含むぼかしを下敷きにしない。元位置は修復済み背景または背後部位から描画し直す。
アルファ境界は小さい内側のfeather、RGBの背景色汚染除去、テクスチャ端の色延長、premultiplied alphaでハローを減らす。太い線を広いblurで溶かす方式は採用しない。

## 13. UI/UX

基本導線は **画像投入→解析→点の確認→範囲の確認→動き選択→直接調整→動画保存**。問題がない解析/範囲確認は省略できる。
中央は大きいプレビュー。左は現在の作業に必要な操作、右は選択部位の少数の設定、下は再生/時間/出力。初期画面に大量の技術パラメータを出さない。
選択点のドラッグは骨格位置の修正、手足のドラッグはIK目標の調整、胸/髪等のドラッグは局所ハンドルの調整と、モードの意味を明示する。元姿勢編集と動作編集を切り替える。
ブラシには追加/除外/保護/背景修復を用意。Undo/Redo、ズーム/パン、元画像との比較、前後の重なり変更、処理キャンセル、失敗時の再試行を用意する。
前後の順序は推定候補を提示するがユーザー修正を正本とする。最初は安定した描画順と動作制限を採用し、周期内での複雑な遮蔽の入替えは明示的な順序キーフレーム/重なりマスクで指定する。

## 14. ローカル処理・配布

**主製品はTauriデスクトップアプリ。内部の編集エンジンはWeb技術で共通化する**。単一HTMLは最終配布形式にしない。開発/検証用Web版は同じエンジンを使い、別実装にしない。
TauriはOSのWebViewを利用する構成。[S6] 配布対象はまずWindows。WebView/GPU機能は実機検査し、Windowsでの導入方法・必要runtimeを配布品質ゲートで確認する。Electronのブラウザ同梱方式は初期採用しない。PWAは将来の別配布先として接続点だけ確保する。
モデル、WASM、依存ライブラリ、必要なnative backendを同梱、または利用前にローカルmodel packとして導入する。画像処理・解析・補完・保存・出力を完全ローカルで完結させる。CDN/APIを通常操作の必須条件にしない。
ONNXはWebGPUを優先し、対応しないモデル/端末ではWASM CPU、重い補完では必要に応じnative CPU/GPU backendへ切り替える。MediaPipeは専用runtimeで実行し、ONNXモデルだと扱わない。失敗するGPU設定を自動的に繰り返さない。
Workerで解析/素材生成を分離し、長時間処理は進捗とキャンセルを返す。WASMの複数スレッドが使えると仮定せず、cross-origin isolation等の条件を確認し単一スレッドでも動く経路を残す。

## 15. 保存・出力

プロジェクトはZIPコンテナ：version付きmanifest JSON、原画像、PNGマスク/背景/補完素材、binaryメッシュ/ウェイト、骨格、局所変形、重なり、モーションクリップ、model metadata、ユーザー補正。巨大なbase64 JSONを正規形式にしない。
UI状態も文書状態から保存する。安定IDと配列順序を維持する。デコードをすべて待って検証してから一括commitし、失敗時は現在のプロジェクトを保持する。循環親子、非有限値、寸法不整合、未知version、欠損素材を検証する。
ローカル自動保存、クラッシュ復旧、原子的なファイル置換を用意する。v6 JSONは画像/マスク/点/順序を取り込む移行機能を実装する。古いアニメーション数値は参考値へ変換し、元の動きを完全再現すると約束しない。
出力はPNG、PNG連番、動画。デスクトップの標準動画はMP4/H.264、FFmpeg等の固定されたlocal encoderへフレームを送る。encoder/codecの配布条件と実機動作を出荷前に確認する。Web検証版は対応codecを検出したWebMを補助出力とする。
最終動画は画面の実時間録画を使わず、指定FPS/尺/解像度で固定時刻を進めるフレーム書出し。フレーム/encoderをqueue制御してメモリ増大を抑える。表示のFPSと無関係に尺を一致させる。
解析用の縮小座標と原解像度座標の変換を文書モデルに保持し、元画像解像度で出力できるようにする。大型画像は上限を検査して縮小編集/分割出力を提示する。

## 16. v6から流用するもの

画像選択/貼付け/D&Dの入力導線、ブラシstrokeの基礎、mask editingの操作概念、骨格点ドラッグの操作概念、ファイル名処理、PNG出力の基礎、presetの意図/名前、既存projectの素材と移行知識。
コードは小さい独立関数だけを検証して移す。旧DOM/グローバル状態への依存が強いUIイベントはそのままコピーしない。

## 17. v6から置換するもの

部位全体affine描画、固定比率を自動認識とする配置、直線カプセル主体の腕脚抽出、数値加算の親子同期、独立sin波の全身動作、元画像をぼかす背景補完、暗さ主体の輪郭回収、全画像を毎フレーム処理するcache設計、停止/再開の時間管理、base64 JSONの正規保存、非同期完了順の復元、画面録画主体の最終出力、単一HTML/DOMと内部状態の直結。

モデル非依存の解析interface、候補/可視性/信頼度、semantic rig、IK/接地、輪郭と関節を考慮したmesh生成、weight生成/補正、関節補正、spring/局所変形、画素所有と遮蔽、背景と隠れた部位の別補完、保護/clone brush、Undo/Redo、dirty依存管理、deterministic timeline、checkpoint、local自動保存、原子的復元、offscreen export、性能診断、Tauri配布。

## 19. 実装順序と合格条件

| 段階 | 実装する範囲 | 動作確認/合格条件 |
|---|---|---|
| 0 | 対象環境、PixiJS/WebGL2、モデル/encoder互換性の小検証 | 実機のGPU/推論/入出力確認。確認できないmodelは製品依存に固定しない |
| 1 | 文書モデル、core rendering、最小project保存読込 | 原姿勢で入力と一致。透過/描画順/復元順を保持 |
| 2 | 手動rig、mesh、skinning、関節補正 | 肘/膝/肩が曲がり、付け根が裂けず長さを維持 |
| 3 | mask/所有/境界、部位抽出の編集 | 同じ画素の不要な二重描画をせず、brush補正可 |
| 4 | timeline、主動作preset | 停止/再開/seekが一致、speed/powerが全体へ一貫して反映 |
| 5 | 親子行列、IK/接地、spring/局所変形 | 関節の接続保持、低FPSで暴走しない、余韻が自然 |
| 6 | 背景/隠れ部位補完、輪郭修復 | 元位置に人物の二重線がなく、露出領域に破綻しない |
| 7 | 身体解析、prompt segmentation、anime評価 | 手動生成と同じrigに到達、低信頼点を修正可。自動化品質を測定 |
| 8 | 一連のUI、Undo/Redo、直接調整 | 理想導線を中断なく完了できる。再解析が補正を消さない |
| 9 | Tauri、自動保存/復旧、v6移行、動画出力 | model同梱時はoffline完走。破損読込で現project保持。指定尺の動画を書出し |
| 10 | 統合テスト、性能/画質の改善 | anime評価画像、透過/太線/重なり/座り/上半身/大型画像で確認 |

最小保存読込と文書モデルは最初から含める。高度な保存/配布/出力は後半で仕上げる。自動解析を先に巨大実装せず、手動で正しいrigを作れることを先に確認する。通常操作の基本UIは各段階に必要な分だけ付ける。
性能目標は原寸2048px級、1人物、10～20描画部位、数千～1万頂点程度で快適な編集と30fps以上、対応機では60fps。これは設計目標であり未測定。基準PCを段階0で明示する。推論は準備時のみで再生中には実行しない。

## 20. 主な技術リスクと扱い

| リスク | 扱い |
|---|---|
| anime pose/segmentationが安定しない | 評価画像と修正量で判定、model差替え、手動経路を維持。自動化の品質未達は明示 |
| 重なった腕と胴、見えない背景/体 | 可視性/遮蔽順を保存。小動作を基本にし、補完素材/修正導線を用意 |
| meshの潰れ/反転/線の伸び | 関節密度、局所補正、可動域制限、weight検査、同一接続点 |
| alpha halo、消しすぎ、二重線 | 3種mask、線幅ベース修復、保護brush、境界色補正、原画像比較 |
| spring暴走、loop/seek/export差 | fixed timestep、上限、warm-up、checkpoint、同じシミュレーション経路 |
| WebGPU/ONNX/LaMa互換性・メモリ | 実modelで先行検証。WASM/native fallback、順次session、crop/解像度制限 |
| Tauri WebView/codec/配布重みの依存 | Windows実機検証、runtime確認、固定版とライセンス記録、offline package確認 |
| 再解析で編集が消える/壊れた保存 | 原画像不変、編集と候補を分離、世代ID、transaction、schema migration |

### 決定の強さ

上記のエンジン構成、同期/変形方式、素材モデル、UI導線、local優先、実装順序を正式方針D1とする。
MediaPipeは初期pose候補、MobileSAM/LaMa系は初期評価model候補。個別modelの重み・変換版・実行provider・性能は、実装前の互換性検証で固定する。未検証のmodelを「アニメ絵に対応済み」「ブラウザで動作済み」と扱わない。これはアーキテクチャ未決定ではなく、model適合性の品質ゲートである。
大きい動きを無理に許すより、元絵を保って自然に見える可動域と修正量の少なさを優先する。
